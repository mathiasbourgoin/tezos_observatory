# Product specification

Tezos Observatory is a static TypeScript browser application for observing Mainnet and Shadownet consensus. It opens RPC streams only while the page is visible and collection is active. No server collector, signing, wallet access or node mutation is part of the product.

Observers must identify the applied head and selected consensus instance, distinguish received proposals/votes from calculated opportunities, inspect phase-specific committee participation, and understand source limitations. The selected identity includes network, level, round and payload; candidate block identity distinguishes proposals that may share a payload. Producer labels require evidence matching the selected candidate.

V3 must deliver compact independent network/source summaries and a full-width inspector; selectable competing candidates; bounded session history; distinct pin/follow-live/collection-pause controls and newer-items notification; searchable phase-specific committee evidence; eligibility context/freshness; separate selected producer, next same-level round and conditional next-level opportunities; bounded independent source comparison without manufacturing a combined quorum. Receipt timelines, watched filters and recovery celebration are conditional features: adoption must be recorded explicitly, and timestamps cannot invent original arrival time. Celebration, if adopted, requires detected chain stall followed by observed level recovery, never initial connection or RPC reconnection alone.

The visual implementation must be beautiful, practical and original in composition and interaction. ASTRA researches current cross-chain observer products and the supplied design references, compares structurally different directions, implements the chosen design directly, then iterates using actual rendered states. A palette swap is insufficient. Use an original palette without defining blue/violet accents, persistent light/dark choice, deliberate phone-to-ultrawide layouts including 3440/5120-pixel verification, and restrained meaningful motion with reduced-motion usability. Asset choices need product purpose, provenance and coherent treatment.

Acceptance: exact instance attribution and quorum accounting; unknown distinct from zero; stable pinned selection, keyboard focus and scroll across multiple updates; complete loading/empty/error/divergent states; readable long aliases and exact values; exercised keyboard/touch controls; sufficient rendered contrast in both themes; clean Node 22 checks and Chromium/Firefox production-page scenarios. Independent visual review and bounded live-origin checks supplement synthetic tests. Publication/deployment remains a separate maintainer decision.
