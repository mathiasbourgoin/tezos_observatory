## 3. Identified risks

- **The integrated baseline is a real blocker, not a formality.** Mutable V3 edits can invalidate lifecycle ownership and regression evidence even if local interval tests pass. Require a named immutable revision before edits and exact final review source.
- **Layer-only decomposition hides the highest risks.** Shipping calculator, then transport, then UI as isolated steps can postpone discovery of real lifecycle and reader regressions. Steps2–5 deliberately grow the real production path, with calculation/acquisition helpers subordinate to each vertical slice.
- **Concurrency plus deadlines can exceed bounds after apparent completion.** Abort alone does not settle hostile doubles; dangling workers can start fallback/recheck requests late. Explicit settlement/generation guards and bounded scheduling are essential.
- **The recheck can be starved by work ordering.** Three floors, optional fallback and 8s per-read deadlines must leave room for fixed-E validation under24s. Do not assume all independently valid reads guarantee batch completion; batch timeout correctly retains stale prior data. Tests should cover worst scheduling, not only fast mocks.
- **JavaScript numeric safety is wider than field safety.** Safe individual levels/timestamps do not automatically establish every elapsed-age or level/time-difference operation is safe. Validate intermediate arithmetic and avoid an accidental zero display.
- **Selection assertions differ from pair validity.** Reversed endpoints may be individually valid insufficient data only when query assertions are satisfied; a floor above E or newer than C is unavailable. One catch-all invalid branch would erase this distinction.
- **Fallback is conditional per window.** A single earliest result can support one cutoff and contradict another. Shared transport success must not imply all dependent windows are partial.
- **Freshness creates several easily conflated clocks.** Completion freshness, batch T, metadata receipt and endpoint-age baseline answer different questions. Reusing one wall timestamp or selected E.level for lag would produce misleading output.
- **Refresh disabled state does not alone enforce the contract.** Programmatic calls and queued material changes must share eligibility checks; no UI timer may turn cooldown expiry into acquisition.
- **A successful batch may still contain unavailable windows.** Reusing old numerics per failed window would silently mix as-of times. Conversely shared failure must not commit even successful floors.
- **Disclosure-heavy design could fail the product requirement.** Source and real coverage must be legible without opening specialist details, especially on short phones; dumping full evidence inline could obscure the existing overview.
- **Large presentation matrix can become nominal evidence.** The acceptance criterion must actually assert values/states/reader preservation on the production region, with contrast measured against composed surfaces and a fresh independent manual check.
- **TzKT semantics remain provider assertions.** Fixed-E equality does not prove intermediate continuity or malicious-provider honesty, and no RPC fallback or new global health authority is permitted.
