# Block intervals — fresh requirements formalization

Requirements evidence only; no implementation, test execution or acceptance pass is claimed. Sources read in full: validated intake, three-story draft, resolved Q1–Q8 and binding C-1–C-17. Binding resolutions supersede ambiguous draft wording. Each AC below has a proposed same-number CHECK interface; neither runner nor execution is claimed. Story scenario references use US-N/SN. These requirements add to all 323 mandatory inherited claims.

## Functional requirements

### US-1 — Compare completed-block intervals

| ID | Actor / trigger / required outcome | Trace |
|---|---|---|
| FR-001 | For an observer starting a batch, the metric MUST capture one finite wall T and wall/monotonic start receipts and MUST offer exactly the ordered 604800/86400/3600-second windows, with unrounded C=T-duration independent of civil-time changes. | US-1/S1; AC-1 |
| FR-002 | When selecting endpoints for an observer, the metric MUST select latest descending-level indexed E at/before T and descending-level S at/before each C, constrained to E.level; exact cutoff equality MUST qualify and the full crossing interval MUST count without weighting. | US-1/S1–3; AC-1, AC-18 |
| FR-003 | When computing a valid pair for an observer, the metric MUST retain integer milliseconds until division, calculate elapsed seconds divided by E.level−S.level, and retain the unrounded mean; n=1, irregular intervals, protocol transitions and skipped observations/large level gaps MUST preserve that denominator. Ongoing wait and protocol delay MUST NOT enter arithmetic. | US-1/S1–2,6; AC-1, AC-6, AC-18 |
| FR-004 | When only empty floor arrays lack S, the metric MUST permit at most one shared ascending-level earliest lookup bounded to E; each dependent window MUST require earliest newer than C and no later/higher than E, label a usable pair partial available history and disclose actual extent. | FR-005 | When endpoints cannot produce a value, the metric MUST distinguish valid individually parsed but nonpositive/unsafe pair arithmetic or E<=C as insufficient data, from malformed/missing fields or violated selection assertions as unavailable, with the exact reason; it MUST NOT shift C, guess a mean, or show zero/Infinity. | US-1/S5; AC-4 |
| FR-006 | When parsing source endpoints, the metric MUST require safe nonnegative integer levels, nonempty hashes and calendar-valid timezone-bearing timestamps with seconds or 1–3 fractional digits; it MUST reject greater precision, preserve original timestamp strings and compare normalized millisecond instants for consistency. ## Public check and evidence contract

Planned CHECK-N uses the proposed guarded `scripts/check-observatory-block-intervals.mjs` module interface `run(["AC-N", "--browsers", "chromium,firefox"])`. It returns `{code:0|1, assertions:positiveInteger}` only after all selected behavioral assertions actually execute. Behavioral mismatch is RED/exit1 only after an assertion fires. Missing runner/import/build/fixture/browser/setup, unsupported AC, missing production-consumer execution, zero assertions or unhandled page execution error MUST be ERROR/exit>=2, never RED or GREEN.

All reader/lifecycle criteria MUST execute the actual served production build in both requested real engines; source inspection, fake browser, one engine, child exit0/report existence or a unit reimplementation cannot satisfy that boundary. Calculation/acquisition checks MUST invoke the real production consumer with deterministic facts. Evidence MUST name immutable integrated revision, actual command/engine/cases/assertions/outcomes and demonstrate every obligation, beyond an assertion count. Live provider smoke establishes only bounded instantaneous availability. Existing release/regression gates remain required; this formalizer ran none.
