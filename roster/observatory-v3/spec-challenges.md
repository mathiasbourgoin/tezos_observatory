## Challenges

- **C-1 [US-1-S1/S2]**: “Selected network/source/context/level/round/payload” does not enumerate a selectable candidate's hash or distinguish selected instance from selected candidate in S1. Which exact selected identity must remain inspectable when H1/H2 share P, and which power/signature labels prevent a reader from interpreting shared P evidence as two candidate-specific endorsements? Foundation C-1 prohibits that inference; an actual matching producer cannot be inferred from payload equality alone.
- **C-2 [US-1-S3; US-5-S2]**: “Usable exact source snapshot with zero” and “partial/unavailable” need their accepted evidence predicates carried forward. Which receipt/coverage/rights/context facts justify zero independently for each phase, and how is truncated candidate/provenance history prevented from certifying zero or completeness under foundation FR-093?
- **C-3 [US-2-S1/S3]**: “Coherent adjacent actual r1” does not say which observed relationship is proven when votes-only r0 lacks a block hash. What evidence allows an observed round-direction relation, what separately allows a solid verified ancestry edge, and how does the navigator avoid treating coordinates or matching payload as block ancestry?
- **C-4 [US-2-S3; US-4-S2]**: Reorg invalidation withdraws old H1 authority, while a frozen pin is “static.” If invalidation arrives after freezing, does static describe immutable recorded historical facts, or continued current authority? Which labels distinguish the recorded as-of context from a current live claim without replacing the frozen evidence or admitting it to LIVE?
- **C-5 [US-2-S4; US-7-S2]**: The one-animation/RIGHT final-batch policy is accepted, but “one burst” and the final destination are not observable criteria by themselves. When r1 and a next-level observation arrive while a 160ms transition is already running, what observable timing/motion bounds demonstrate replacement/coalescing rather than a second queued reenactment, and what prevents a gap/reorg inside that batch from receiving smooth progress styling?
- **C-6 [US-3-S1/S2]**: “Both targets/proposers/timer labels simultaneously readable in the local overview” lacks a viewport-height or clipping qualification. Does simultaneous mean one intact overview region after ordinary vertical navigation, or everything in the initial device viewport? What measurable minimum text/target legibility and long-proposer presentation will distinguish success from mere DOM presence at 360/390px?
- **C-7 [US-3-S3; US-4-S1]**: Actual captured opportunities are required, not recomputation at historical-selection time. If an observation has no captured rights/timing, or only one branch has a captured deadline, which per-branch state appears upon historical selection? How is later same-identity rights/timing arrival distinguished from permitted vote enrichment so a historical pin does not gain an invented capture?
- **C-8 [US-4-S2/S3]**: The story covers session eviction but not active-index candidate eviction while its instance remains retained. How do selectable history, Previous traversal, partial candidate retention and pin enrichment remain consistent with foundation FR-091's retained historical candidate facts, 100-fact snapshot bound and freeze-on-history-entry-eviction rule?
- **C-9 [US-4-S1/S3]**: “First accepted monotonic receipt” and “candidate-free promotion does not duplicate an instance” must retain the foundation identity/tie semantics. When the candidate-free instance already contributed one newer item and later H1/H2 appear at the same receipt time, which distinct identities count, how is promotion excluded, and which deterministic tie order drives Previous without reordering already read identities?
- **C-10 [US-4-S4; US-5-S3]**: Paused/hidden work cancellation is inherited, yet the stories do not state whether an explicitly requested comparison just before hiding retains an attributed stale result, shows cancellation, or can regain freshness on return. How do exact generation/context cancellation, sticky invalidation and independent manual-pause state remain visible without silent reads?
- **C-11 [US-5-S1]**: Reader order is stable until explicit resort, while search/aliases determine membership. When an existing row stops matching after alias correction, or a power sort is chosen while power is unknown for some rows, which observable membership/order semantics apply? Which inherited C-18/C-19 rules answer these cases rather than inventing a new automatic sorting policy?
- **C-12 [US-5-S3]**: “Max three reads” alone allows incompatible choices. Which exact compared fields can be proven by identity/head/pending under foundation FR-094, what establishes pending's unavailability before a different third read, and how is original source provenance retained for compatible cached rights so B never appears to certify A's rights?
- **C-13 [US-6-S1/S3]**: “Deliberate meaningful regions,” “original” and “legible” can pass arbitrary visual judgment. Which accepted production evidence makes dense usability, readable full hashes/aliases, paired exact powers and useful 5120px space assessable independently of zero overflow or resemblance to an approved sparse study?
- **C-14 [US-6-S2]**: “Honest fallback” does not identify the observable state when persisted data is corrupt or storage denies writes. Which usable initial/changed theme state and system-preference behavior are required, and how will the reader know whether the current choice survives reload without a crash?
- **C-15 [US-7-S1/S2]**: “Usable touch targets,” “logical reading order” and “meaningful status announcement is coalesced” need observable acceptance boundaries. Which control dimensions/spacing/exceptions and keyboard paths are applicable, and which status changes are announced without repeated vote narration, duplicate graph/text controls or focus displacement?
- **C-16 [US-8-S1/S2]**: Preservation names “original foundation 38 acceptance checks,” while the active foundation contract now maps 94 FRs and broadened obligations to those same 38 ACs. What revision identifies the required accepted foundation checks, and what prevents preserving stale scripts or an earlier 90-FR projection while omitting the active FR-091–094 behavior?
- **C-17 [US-8-S2]**: “Full required width/theme/state/interaction matrix” can mean the complete Cartesian product or a documented representative assignment. Which combinations must actually be rendered and measured, including Chromium versus Firefox, viewport heights, expanded full values and interactive surfaces, so a coverage report cannot call an untested combination complete? How do runnable checks establish entrypoint existence/syntax preflight and distinguish assertion failure (1) from missing/load/syntax/browser/fixture/runtime error (>=2), as root explicitly clarified, instead of counting a native missing-file exit 1 as behavioral evidence?
- **C-18 [US-1-S2; US-2-S2; US-8-S1]**: A selection must not fabricate a threshold event, but replay/retirement may outlive visible history. How do production assertions establish inherited at-most-once per phase/identity/context and first-observed-quorum semantics across eviction, retired replay and a proven reorg return under foundation FR-092, without mistaking new renderer state for a new crossing?

## External prior-art challenges

The entries below explicitly cover all ten rows of `roster/observatory-v3/research.md` → External prior art. They challenge documented differences or unsupported transfer; they do not claim the references prove this product's usability.

- **C-19 [US-2; US-4; US-6]**: Prior art: **Forky** shows retained fork-choice data, time navigation, source-specific heads and a head-focus control ([repository](https://github.com/ethpandaops/forky), [rendered Mainnet](https://forky.mainnet.ethpandaops.io/)); the stories assume bounded session receipt navigation, one-off Latest versus ongoing Follow and docked evidence rather than its overlapping floating source table — justify the divergence or adopt the documented approach. Which observable labels prevent Forky-like navigation from implying server history, cross-source pooled authority or Ethereum finality here?
- **C-20 [US-5; US-6; US-8]**: Prior art: **The Lab** documents curated network views distinct from raw Xatu data, several domain routes and multiple themes ([introduction](https://ethpandaops.io/posts/the-lab/), [running Lab](https://lab.ethpandaops.io/)); the stories assume one selected-instance workspace with source-limited raw evidence and light/dark/system choice — justify the divergence or adopt that approach. What visible distinction keeps curated presentation from suggesting complete collector coverage or treating features described as upcoming in the 2025 source as implemented precedent?
- **C-21 [US-2; US-3]**: Prior art: **mempool.space** uses a top strip separating future projected blocks from numbered mined blocks and approximate times ([rendered site](https://mempool.space/), [projected-block source](https://github.com/mempool/mempool/blob/master/backend/src/api/mempool-blocks.ts)); the stories assume two perpendicular conditional branches and exact selected-relative targets — justify the divergence or adopt that approach. How do both branch identities and conditional/unavailable timing remain unmistakable where a compact phone arrangement resembles a sequence of block predictions?
- **C-22 [US-4; US-5]**: Prior art: **Perfetto** documents pinned tracks, reversible filtering and a separate details drawer ([UI documentation](https://perfetto.dev/docs/visualization/perfetto-ui)); the stories assume a pin on an observation identity that allows same-identity evidence enrichment, freezes captured opportunities and is independent of collection — justify the divergence or adopt track-position pin semantics. Which captions and behavior prevent the term “pin” from promising a fully frozen retained evidence view or a paused collector?
- **C-23 [US-2; US-4; US-6]**: Prior art: **Chrome Performance** uses trace overview, selection, range breadcrumbs and linked highlights at multiple scales ([reference](https://developer.chrome.com/docs/devtools/performance/reference)); the stories assume ordinal level/round coordinates and receipt-history selection without elapsed-time distances — justify the divergence or adopt that approach. How does bounded navigation communicate actual retained nodes without a visual range implying missing elapsed-time samples or block ancestry?
- **C-24 [US-2; US-3; US-7]**: Prior art: **100,000 Stars** reveals names at closer scales and explicitly distinguishes measured star positions from an artistic galaxy ([creator archive](https://experiments.withgoogle.com/100000-stars)); the stories assume essential current/both-future labels remain readable together and semantic zoom only reveals secondary evidence — justify the divergence or adopt the zoom-dependent reveal. Which mandatory information may never disappear through zoom/pan, and what marks illustration versus actual observations and qualified predictions?
- **C-25 [US-6; US-7]**: Prior art: **Cameron's World** builds a continuous authored linked collage from historic GeoCities material ([creator page](https://www.cameronsworld.net/)); the stories assume one coherent composition with dense operational evidence, restrained motion and accessible controls — justify the divergence or adopt the collage approach. What evidence shows spatial authorship without importing tiny targets, animation density or borrowed graphics that contradict the operational contract?
- **C-26 [US-6; US-8]**: Prior art: **Sikora's critique** rejects repeated cards, rigid symmetry, indigo/violet and large-screen emptiness, but its AI-authorship identification assertions are unsupported by controlled evidence ([editorial](https://sikora.software/blog/ai-website-design)); the stories assume independent reasoned visual critique as an acceptance gate — justify divergence from authorship inference or adopt its criterion. Which observable composition/usability defects can fail the gate, without unsupported attribution or punctuation/familiar-control preferences becoming requirements?
- **C-27 [US-3; US-8]**: Prior art: **Octez consensus documentation** derives rounds/proposal timing from protocol rules and predecessor context ([primary documentation](https://octez.tezos.com/docs/active/consensus.html)); the stories assume concrete frozen 6s/deadline examples and selected-relative r1 even when the clock estimates r7 — justify any divergence from context-dependent calculation or adopt it. Which scenario assumptions prove that those values are fixtures/captured facts rather than hard-coded current protocol truth, and which context is being calculated for each visible timer?
- **C-28 [US-6; US-7; US-8]**: Prior art: **W3C guidance** gives applicable 4.5:1 ordinary-text, 3:1 qualifying-large-text/control/graphic contrast and documented target-size exceptions ([target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [text](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [non-text](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)); the stories assume “readable,” “usable” and “applicable contrast” without enumerating applicable surfaces/exceptions — justify any divergent acceptance threshold or adopt those criteria. How are disabled, selected, threshold-marker-on-fill, focus, tooltip and native-control surfaces included or legitimately excepted in actual rendered measurements?

## Edge Cases

- **EC-1 [US-1]**: H1/H2 share P, H3 has Q, selected hash changes while P is already at quorum → shared P labels remain attributable, Q is independent, no candidate-specific endorsement/producer inference or fabricated crossing.
- **EC-2 [US-1; US-5]**: Preattestation snapshot proves zero but attestation coverage is interrupted; retained facts also truncate → phase states stay separate and truncation cannot establish zero/completeness.
- **EC-3 [US-2]**: Observed r0 is eligible while clock estimate passes r6/r7 and prediction r1 expires → observed anchor remains r0; no invented observed rounds or camera/history advance.
- **EC-4 [US-2]**: Votes-only source has coherent same-level adjacent round but no proposal hash → observation direction and verified-ancestry edge must remain distinct; precise qualifying evidence requires challenge resolution.
- **EC-5 [US-2; US-7]**: Next-level receipt follows r1 during an in-flight animation, while final context is a gap or reorg → at most one motion in flight, no queue/fabricated path; gaps/reorgs static with status; burst membership criterion unspecified.
- **EC-6 [US-2; US-4]**: Applied same-height H1 becomes H2 while old successor r0 is pinned/frozen → old evidence never remains live eligible; captured historical facts remain attributable; frozen-versus-current authority label requires resolution.
- **EC-7 [US-3]**: Only one historical branch has captured rights/timing; other facts arrive after capture → no current-rights borrowing or invented capture; exact later-fact presentation unspecified.
- **EC-8 [US-3; US-6]**: 360px phone has long proposer labels, full disclosures and short viewport height → both essential future options remain readable in the overview; initial-viewport versus intact-region height interpretation unspecified.
- **EC-9 [US-4]**: Active candidate index evicts H2 but its full session instance/pin remains retained → historical inspection remains available under foundation FR-091; no premature fully frozen pin.
- **EC-10 [US-4]**: The 151st session instance evicts the selected oldest pin → one static per-network copy outside history, Previous unavailable; explicit Latest pins newest coherent LIVE or shows unavailable; Follow enables ongoing mode independently of pause.
- **EC-11 [US-4]**: Candidate-free item promotes to H1, sibling H2 arrives with same monotonic receipt → no duplicate instance promotion count; tie/traversal details must preserve accepted foundation order.
- **EC-12 [US-4; US-5]**: Comparison response returns after pause/hide/context switch and user returns to old context before 60s → obsolete result cannot commit as fresh agreement; invalidation remains sticky; no silent refresh.
- **EC-13 [US-5]**: Alias correction removes an existing query match while a new row matches; unknown power appears during power sort → query membership and order behavior need inherited-rule trace; no unsolicited resort.
- **EC-14 [US-5]**: Source B rights are uncached and pending is unavailable within the three-read workflow → no fourth read/retry; only proven fields compare, compatible cached rights retain their own provenance, power otherwise unknown.
- **EC-15 [US-6]**: Storage parse fails or write is denied; OS theme changes after an explicit in-memory choice → app remains usable, OS affects system mode only; visible persistence-fallback semantics unspecified.
- **EC-16 [US-7]**: Reduced motion is requested during active live transition and incoming votes continue → observed destination has static equivalent, focus/scroll stay fixed; switch-during-motion behavior needs accepted-policy trace.
- **EC-17 [US-8]**: Retired identity replays quorum after visible history/crossing memory retirement → no invented crossing; uncertain prior history is observed-quorum/raw evidence under FR-092, not fresh event.
- **EC-18 [US-8]**: One required browser/command/state render fails or cannot load → report error and missing evidence, never green substitutes; provider failure stays source-bounded unknown.
- **EC-19 [US-8]**: Report revision differs from tested source or concurrent foundation edits change active obligations → acceptance must bind exact tested source/contract; earlier study or claims-active labels cannot establish production proof.
