# Context authority research — slice 3

Read-only supporting researcher verified official Octez RPC/source evidence for FR-025–032/090. This is implementation evidence design, not passing product verification.

- `/chains/main/chain_id` returns the actual observer's chain identifier. Configured network/name does not prove it. Validated-block monitor embeds `chain_id`; head monitor does not. Head events describe validated/applied selection; validated-block events do not yet establish applied/stored context. [Official shell RPC reference](https://octez.tezos.com/docs/shell/rpc.html).
- `/chains/main/blocks/H/header` returns flattened `hash`, `chain_id`, shell predecessor and decoded header fields. `/header/shell` alone lacks hash/chain identity. `/blocks/H/protocols` returns exact current `protocol` and successor `next_protocol` hashes. [Official block services](https://github.com/tezos/tezos-mirror/blob/master/src/lib_shell_services/block_services.ml#L454).
- Helpers/context RPCs under H execute H's **next protocol**, while H's header/operations decode with H's producing protocol. Consequently current-level H rights/constants cannot blindly use H's helper protocol at activation: current H targets need exact predecessor context with proven compatible successor protocol; successor targets use H and H.next_protocol. This is an inference from [official directory registration](https://github.com/tezos/tezos-mirror/blob/master/src/lib_shell/block_directory.ml#L790).
- Shell `proto` is an 8-bit protocol-level counter, not a protocol hash. Current/next protocol resolution depends on predecessor/current protocol level, and pruning can remove stronger distinctions. [Official block directory implementation](https://github.com/tezos/tezos-mirror/blob/master/src/lib_shell/block_directory.ml#L108).
- Current alpha rights response is `[{level,delegates:[{delegate,first_slot,attesting_power,consensus_key}],estimated_time?}]`. Older protocol APIs may use `attestation_power`, so unsupported schemas must remain unknown rather than silently inferred. [Current plugin encoding](https://github.com/tezos/tezos-mirror/blob/master/src/proto_alpha/lib_plugin/RPC.ml#L4100), [ParisC API](https://octez.tezos.com/docs/api/odoc/_html/octez-protocol-020-PsParisC-libs/Tezos_protocol_plugin_020_PsParisC/RPC/Attestation_rights/).

Required fixtures: flattened chain-aware header versus shell-only data; activation with Pold/Pnew and exact current/successor anchors; same-height H1/H2 with delayed H1 rights/eligibility; actual fallback endpoint and incompatible chain/context; identical shell proto/level on forks; mismatched predecessor despite equal level; eligibility fresh at 59999ms and stale at60000ms with sticky invalidation; compatible comparison rights retaining original source. No parent is inferred from a level and no protocol hash is inferred from a label/counter.

## Active Ushuaia fitness corroboration

The exact observed protocol is declared by [Ushuaia TEZOS_PROTOCOL](https://github.com/tezos/tezos-mirror/blob/master/src/proto_025_PsUshuai/lib_protocol/TEZOS_PROTOCOL#L3). Supporting research found its fitness/round source byte-for-byte identical to the checked alpha rules. [Fitness structure and lock constraints](https://github.com/tezos/tezos-mirror/blob/master/src/proto_025_PsUshuai/lib_protocol/fitness_repr.ml#L136), [context level/predecessor validation](https://github.com/tezos/tezos-mirror/blob/master/src/proto_025_PsUshuai/lib_protocol/fitness_repr.ml#L264), [signed nonnegative round range](https://github.com/tezos/tezos-mirror/blob/master/src/proto_025_PsUshuai/lib_protocol/round_repr.ml#L74), [raw level range](https://github.com/tezos/tezos-mirror/blob/master/src/proto_025_PsUshuai/lib_protocol/raw_level_repr.ml#L87), [fitness version 02](https://github.com/tezos/tezos-mirror/blob/master/src/proto_025_PsUshuai/lib_protocol/constants_repr.ml#L33).

Five fields are version02, signed nonnegative level, optional signed nonnegative locked round strictly smaller than round, signed negative predecessor encoding `-predecessorRound-1`, and signed nonnegative round. Level must match the shell level. `ffffffff` in the predecessor field means prior round0; it is invalid in the actual round field. Unsupported/malformed/legacy fitness remains unknown rather than fabricated round0. No additional provider polling was performed.
